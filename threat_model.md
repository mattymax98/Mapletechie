# Threat Model

## Project Overview

Mapletechie (mapletechie.com) is a production tech-blog platform built on a pnpm monorepo. The stack is React + Vite (frontend) served by a Node.js/Express 5 API, backed by PostgreSQL via Drizzle ORM. It is deployed publicly on Replit Autoscale. Users are unauthenticated readers and a small, trusted set of internal editors/admins who manage content through an admin panel.

## Assets

- **Admin credentials** — username/password pairs for editors and the founding admin (`matthew`). Compromise gives full content management capability (create, publish, delete posts; manage editors; send bulk email; configure maintenance mode).
- **Resend API key** — authenticates outbound email via `resend.com`. Compromise allows sending arbitrary email from `@mapletechie.com` addresses (phishing, spam, quota exhaustion, email log access).
- **Session tokens** — 30-day bearer tokens issued after login. Compromise impersonates the holder.
- **Object storage** — Uploaded images and media files, backed by Replit object storage. Abuse could cause storage/bandwidth cost escalation or serve malicious content.
- **Reader PII** — Email addresses in the newsletter subscriber list, contact form submissions, and job applications. Exfiltration harms subscribers and may trigger GDPR obligations.
- **Published content** — Blog posts, categories, and editorial configuration. Unauthorized modification damages brand reputation.
- **Automation / MCP tokens** — `AUTOMATION_DRAFT_TOKEN` and `MCP_CONNECTOR_TOKEN` allow external AI agents to submit draft posts. Exposure allows spamming the draft queue.
- **AI generation API keys** — Used by `/admin/generate-post`; billed per call. Abuse incurs real cost.

## Trust Boundaries

- **Public Internet → API** — All API routes are reachable from the public internet (deployment visibility: public). Public routes are unauthenticated; admin routes require a valid session token. This is the primary enforcement boundary.
- **Admin panel (frontend) → Admin API** — The frontend applies route guards, but security must be (and largely is) enforced server-side via `adminAuth` + `requireRole`/`requirePermission` middleware.
- **API → Object Storage** — Presigned upload URLs are generated by the API and then used directly by clients (bypassing the API layer for the actual upload). The API is the gatekeeper for granting these URLs.
- **API → Resend (email)** — Outbound emails sent via Resend API. The API holds the secret key; client-side code must never see it.
- **API → PostgreSQL** — Direct DB access. SQL injection would give full DB read/write. Drizzle ORM is used with parameterized queries throughout.
- **API → External image hosts (SSRF surface)** — `persistExternalImage.ts` fetches admin-supplied URLs. An SSRF guard (DNS resolution + private-range check) is implemented.

## Scan Anchors

**Production entry points:**
- `artifacts/api-server/src/routes/index.ts` — aggregates all routes
- `artifacts/api-server/src/middlewares/adminAuth.ts` — session auth middleware
- `artifacts/api-server/src/routes/admin.ts` — editor/admin management
- `artifacts/api-server/src/routes/posts.ts` — post CRUD (largest attack surface)
- `artifacts/api-server/src/routes/storage.ts` — file upload/download (unauthenticated presigned URL endpoint)
- `artifacts/api-server/src/routes/automation.ts` — external AI draft submission

**Highest-risk areas:**
- `.replit` — contains hardcoded RESEND_API_KEY and ADMIN_PASSWORD (plaintext)
- `artifacts/api-server/src/routes/storage.ts` — `POST /storage/uploads/request-url` is unauthenticated
- `artifacts/api-server/src/lib/persistExternalImage.ts` — SSRF guard implementation

**Public vs authenticated surfaces:**
- Public: GET posts/categories/tags/series/search/authors/editors/feed/sitemap/contact/newsletter-subscribe/comments/job-listings/advertise/settings/health
- Editor-authenticated: all `/api/admin/*` routes require `adminAuth`
- Admin-only: role management, content generation, AI features, send-email, newsletter broadcast, site settings, post restore
- Unauthenticated (unexpected): `POST /storage/uploads/request-url`, `GET /storage/objects/*`

**Dev-only areas:**
- `artifacts/mockup-sandbox/` — design mockup, not production-reachable via the main domain

## Threat Categories

### Spoofing / Authentication

Admin sessions are 30-day bearer tokens (64 hex chars, crypto-random). Login goes through `POST /api/admin/login` with bcrypt-verified passwords (cost 10). The legacy `ADMIN_PASSWORD` bearer-bypass was removed. The MCP and Automation endpoints use independent, constant-time-compared tokens. The main risk is credential leakage via the `.replit` config file, which stores both the admin bootstrap password (`ADMIN_PASSWORD`) and the Resend API key in plaintext.

### Information Disclosure

The `GET /editors` public endpoint returns editor usernames, roles, bios, and social URLs — by design for the public "Our Team" page. No passwords or email addresses are exposed. The `GET /storage/objects/*` endpoint is unauthenticated; uploaded objects are served publicly to anyone who guesses or learns the UUID-based path.

The Resend API key is hardcoded in `.replit` (both development and production environments), making it accessible to anyone with repository read access. This key grants the ability to send email from the verified Mapletechie domain, view email logs, and exhaust the sending quota.

### Tampering

Post content undergoes `sanitize-html` cleaning on write. Cover/OG images are validated. Rating values are server-clamped to 0–5. Status is always set server-side (the automation API rejects any client-supplied `status`). The main risk is an editor with `canPublishDirectly=false` abusing a race condition — this is not currently observed.

### Denial of Service

Rate limiting covers login (10/15 min), contact, newsletter signup, comment posting, AI generation, and outbound email. The unauthenticated `POST /storage/uploads/request-url` endpoint has **no rate limiting**, allowing an attacker to generate unlimited presigned upload URLs and trigger large uploads against the object storage backend, leading to storage quota exhaustion and cost escalation.

### Elevation of Privilege

`requirePermission` correctly maps permission flags to actions and lets admin bypass all checks. The `canManageShop` flag remains in the DB but its enforcement was removed — residual `shop` key in the map is harmless (no gated route). The automation and MCP endpoints are gated by independent secrets and always produce draft-only posts attributed to a bot account; forbidden fields (status, authorId, publishedAt) are rejected with 422 rather than silently dropped.
